# P5: Readiness that checks the database

## Problem

A readiness probe that only says "the process is up" keeps a pod in service while it cannot reach Postgres, or while its intake loop has died. A liveness probe that checks the database restarts every pod when the database blips.

## What the template does

- The worker serves a small FastAPI app on `APP_HEALTH_PORT` (8080).
- `GET /ok` is liveness: it answers 200 whenever the event loop runs. It checks nothing else, so a database outage does not restart pods.
- `GET /ready` is readiness: 200 only when the pool is open, Postgres answers `SELECT 1` within 2 s, and the intake loop is alive. Otherwise 503. The body names the result of each check.
- The probe never raises and logs nothing, so it never writes the DSN, which holds the password.
- The Deployment points its liveness and readiness probes at these paths; Compose's healthcheck uses `/ready`.
