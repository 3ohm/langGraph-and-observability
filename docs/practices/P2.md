# P2: PgBouncer-safe mode

## Problem

PgBouncer in transaction mode gives each transaction whichever server connection is free. Server-side prepared statements and the checkpointer's pipeline mode then fail at random, and session state, such as an advisory lock, does not stay with the client.

## What the template does

- `APP_PGBOUNCER_MODE=true` sets `prepare_threshold=None` on every pooled connection, so psycopg never prepares a statement. With the mode off, psycopg keeps its default: it prepares a query after five runs.
- The same setting turns off the saver's pipeline mode (`supports_pipeline = False`), so checkpoint writes run in a plain transaction (upstream issue #8420).
- Session advisory locks do not survive transaction pooling. Run `migrate` with `APP_MIGRATION_DATABASE_URL` pointing straight at Postgres, not at PgBouncer: its lock must hold for the whole run.
- The pruner's leader lock is a session lock too. Behind PgBouncer a single leader is best effort; correctness does not depend on it (P6).
