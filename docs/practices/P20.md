# P20: Deterministic, table-tested assessment rules

## Problem

Asking a model whether to look at code is slow, costs a call, and can change its answer from run to run. A routing decision that nobody can test makes every downstream result hard to trust.

## What the template does

- The `assess` step decides in plain Python whether to collect code evidence: collect code unless there are infrastructure signals and no application signal.
- Infrastructure signals come from Kubernetes reasons, such as `OOMKilled`, `ImagePullBackOff`, `CreateContainerConfigError`, `FailedScheduling`, `Evicted` and `Unhealthy` (a failed probe), and from unhealthy node conditions. Application signals are a stack trace with app frames, or a non-zero exit code.
- Each decision comes with reasons that name the signals and the evidence IDs they came from, never evidence text.
- The rules live in one module, next to their tables, so a fork changes a rule and its table row together.
