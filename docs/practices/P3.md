# P3: Pool-aware checkpointer

## Problem

The stock `AsyncPostgresSaver` (langgraph-checkpoint-postgres 3.2.0) takes one lock per saver around every database call, even when it runs on a pool. With several runs in one process, checkpoint reads and writes then wait for each other, one call at a time.

## What the template does

- `PoolAwarePostgresSaver` subclasses the saver and overrides only `_cursor`: on a pool it takes no shared lock, and each call checks out its own connection, as `AsyncPostgresStore` already does.
- The override copies upstream's private method body. A test pins that method's signature and its use of the instance lock, so an upgrade that changes either fails CI, and the copy is reviewed again or deleted.
- Delete the subclass once upstream stops locking on a pool.
- The checkpoint tables come from `migrate` (the `langgraph` component), never from the worker (P4).
