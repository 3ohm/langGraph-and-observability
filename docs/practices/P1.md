# P1: Pooled, health-checked connections; startup fails without a database

## Problem

LangGraph's docs show a saver on one connection. A worker that runs for weeks on one connection fails at the first network blip, proxy idle timeout or database failover. A worker that starts without its database takes work that it cannot save.

## What the template does

- One `psycopg_pool.AsyncConnectionPool` per process (`create_pool`), with `autocommit=True` and `row_factory=dict_row`, sized by `APP_DB_POOL_MIN` and `APP_DB_POOL_MAX` (1 and 10).
- `check=AsyncConnectionPool.check_connection`: the pool checks a connection before it lends it out, and replaces one that the server or a proxy has closed.
- `max_lifetime` (`APP_DB_MAX_LIFETIME_S`, 1800 s) retires old connections. Keep it below the idle timeout of any proxy or load balancer in front of Postgres.
- `build_conninfo` adds TCP keepalives (idle 30 s, interval 10 s, 3 probes) and `connect_timeout` (`APP_DB_CONNECT_TIMEOUT_S`, 10 s) to the DSN, unless the DSN sets them.
- `open_pool` opens the pool with `wait=True` and that timeout. When Postgres can't be reached, it raises `DatabaseUnavailable`, and the worker exits with an error instead of starting.
- The pool is registered once per process (`persistence/resources.py`), so steps that need the database, such as publishing (P13), use the same pool.
