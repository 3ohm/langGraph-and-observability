# P23: Cache-friendly prompts

## Problem

Bedrock's prompt cache matches on a prefix. A system prompt that holds a timestamp, a run ID or any incident detail is different for every run, so nothing is cached, and every call pays for the full prompt again.

## What the template does

- `SYSTEM_PROMPT` is one fixed text: the role and the rules, with nothing from the incident. It is byte for byte the same for every run.
- The request marks it as the cache prefix: one `system` text block with `cache_control: {"type": "ephemeral"}`.
- It is longer than the minimum that Bedrock caches for Claude Opus 5.5 (512 tokens), so the cache can take it.
- Everything that varies, the target, the assessment and the evidence, goes in the user message, after the cached prefix.
- A change to the prompts or the schema changes `PROMPT_VERSION`, which keys the recorded replies.
