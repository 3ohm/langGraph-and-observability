# P15: Redaction before the LLM and in traces; trace content modes

## Problem

Logs, events and code hold secrets: tokens, passwords, connection strings, keys, emails. Evidence that goes to the model or to a tracing backend unfiltered leaks them to a third party and keeps them there.

## What the template does

- One module, `redaction.redact`, replaces keys, tokens, passwords, connection-string passwords, private keys, email addresses and card numbers with `[REDACTED]`. Each rule is specific: stack traces, hex addresses, SHAs, digests, UUIDs, pod names and timestamps pass unchanged.
- All evidence text passes `redact` before it enters graph state, so the model and the checkpoints see redacted text only. The prompt redacts again.
- Tracing is off unless `LANGSMITH_TRACING=true` and an API key are set. Then one `langsmith.Client` is built with an anonymizer that runs `redact` on every string, at any depth.
- `APP_TRACE_CONTENT`: `redacted` (the default) sends inputs and outputs redacted; `none` sends metadata and errors only; `full` sends everything and is allowed only when `APP_ENV=dev`.
- Tracing errors are logged redacted, and the client is flushed on shutdown.
