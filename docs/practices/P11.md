# P11: Resume at the failed step

## Problem

A run that dies halfway and starts again from the top repeats every external call it had already made, and pays for the model call again. With the default checkpoint durability, the last steps may not be saved when the process dies.

## What the template does

- Each run is one LangGraph thread: `thread_id == str(run_id)`, where `run_id` is a `uuid.uuid7()`. `configurable` holds only `thread_id` (P14).
- The graph runs with `durability="sync"`: each step's checkpoint is written before the next step starts, so a crash loses at most the step that was running.
- A run that has a checkpoint is invoked with `None` input, so it resumes after its last completed step. A run with no checkpoint yet starts from its saved input.
- `APP_RUN_DEADLINE_SECONDS` (900) bounds each attempt.
- The proof runs the test-only three-step graph in worker subprocesses, so it survives the removal of the example agent. The example agent's own end-to-end test kills a worker during its Datadog step.
