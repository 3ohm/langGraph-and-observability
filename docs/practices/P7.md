# P7: Strict serialization with an allowlist, optional encryption

## Problem

Checkpoints are read back into live objects. A serializer that revives any class it is told to, or that falls back to pickle, lets anyone who can write to the checkpoint tables run code in the worker (CVE-2025-64439, CVE-2026-27794).

## What the template does

- `make_serde` builds `JsonPlusSerializer(pickle_fallback=False, allowed_msgpack_modules=...)`: checkpoints are msgpack, never pickle.
- Only the types on an explicit allowlist, each agent's `AgentSpec.serde_types`, and LangGraph's built-in safe types come back as themselves. Any other class comes back as its plain data, such as a dict.
- The allowlist is always passed, so `LANGGRAPH_STRICT_MSGPACK` cannot widen it. The image sets that variable to `true` as well.
- Each allowlisted type must be defined at module level; `make_serde` rejects one that is not, because the serializer could not find it again.
- With `LANGGRAPH_AES_KEY` (16, 24 or 32 bytes) checkpoints are encrypted at rest with `EncryptedSerializer.from_pycryptodome_aes` (AES, EAX mode). That needs the `encryption` extra, which the image installs.
- The serializer tests run with strict msgpack off and on (the `strict_msgpack` fixture): the result must be the same.
