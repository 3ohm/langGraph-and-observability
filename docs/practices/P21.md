# P21: Evals gate pull requests

## Problem

A prompt, schema or rule change can make the agent worse while every unit test still passes. Without a scored dataset in CI, regressions show up only in production.

## What the template does

- The dataset is one case per incident fixture: the twelve sample apps and the infrastructure cases. Each case records the expected category, the expected code location for application cases, and the key facts.
- Evaluators are plain functions: category match, code-location hit, citation validity, and an LLM judge of the root cause.
- Thresholds: category 0.9, code location 0.8, citations 1.0. The eval test fails when an aggregate misses its threshold.
- Normal CI runs the evals in recorded mode with no network (`make test`); the judge is skipped there.
- The Evals workflow runs them against Claude on Bedrock, with the judge, on pull requests and on demand. It gets AWS credentials through OIDC, runs only when `AWS_EVALS_ROLE_ARN` is set, and never for forks or Dependabot. It writes a scorecard to the job summary, linked to the LangSmith experiment.
- `scripts/sync_dataset.py` uploads the cases as a LangSmith dataset.
